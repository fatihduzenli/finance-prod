## Batch A — the workflow (branch `step-13a/batch-a`, plan A1–A2)

**Scope.** Fable measured the migration-test selection on PostgreSQL 16 locally (36 tests, 27:37;
the "over existing rows" cases 21 to 57 s each, the fresh round trips about 60 s) and chose a
split over a squash (a squash would break the tests that target intermediate migrations by name
and rewrite what production has applied; it is 13b's question at the earliest). Fable: the shard
table `ROUNDTRIP_SHARDS` in `tests/conftest.py` (keyed by test name; 17 / 9 / 10 tests, 490 to
545 s each locally), the collection hook that applies the markers `shard1` to `shard3`
(registered in `pyproject.toml`), and `tests/test_ci_shards.py` (every test of the four files in
exactly one shard, the markers reach the tests, the workflow's shape). Opus: `.github/workflows/ci.yml`
— the migration job as a matrix of three shards with `timeout-minutes: 30` and the measured times
in its comment (the TEMPORARY text gone), one "Migration tests complete" check that the deploy job
needs, and the triggers `push: branches: [main]` plus `pull_request:` so a pull request runs once
per commit.

**Findings.** None. One of Fable's own completeness tests had a stale key shape after the table
was re-keyed; fixed before the commit.

**Gate.** ruff, `ruff format --check` (538 files), mypy strict (538 files), `uv lock --check`, `makemigrations --check` (no migration): clean on 6377109. sqlite: the full suite 8,172 passed, 697 skipped, 122 deselected in 1,699 s (the collection hook adds its markers to the four files and changes nothing else). PostgreSQL 16 (a throwaway container): the three shards run one by one as CI runs them — shard 1: 17 passed in 541 s (9:01); shard 2: 9 passed in 462 s (7:42); shard 3: 10 passed in 530 s (8:49); 36 in all, no test twice or missing (the completeness tests) — then the unit selection 8,830 passed, 3 skipped, 125 deselected in 1,764 s and the e2e suite 43 passed four times over (107, 103, 103 and 103 s). Visual: no baseline regenerated (no page changed); 66 passed on PostgreSQL and 66 on sqlite. Secret scans clean; the workflow holds no secret value and its deploy condition is unchanged.

**CI times.** CI_TIMES_A (filled from the pull request's run and the merge run)

**Verdict (A):** PASS for the local gate; the CI times are the acceptance the owner asked for and are recorded from the PR run and the merge run below.


## Batch B — the business data out of the repository (branch `step-13a/batch-b`, plan B1–B4)

**Scope.** Fable. Moved out of the working tree: the nine files of `docs/inputs/` and the real
store-cost rows that `docs/templates/Store_Costs_Template.csv` and `.xlsx` held (517 stores with
towns, operator nicknames and rents, not a template); invented rows of the same shape replace the
two template files and the two-row example and fixture spreadsheets, so the import tests still
pass. Redacted to placeholders in `docs/SCOPE.md`, `docs/COLUMN_MAPPING.md` and `docs/STATUS.md`:
the real store numbers with towns, the August 2026 revenue total and counts, the three staff
names with their roles. The test data's real towns and the August fixture's real total became
invented ones (the fixture's rule keeps an exact remainder on the last row). `docs/inputs/README.md`
says where the files live and that history is not rewritten. A grep for every moved value over
the tree (outside the QA records) finds nothing.

**Where it lives.** The private container `owner-inputs` on the staging documents storage account `stfinancestagingavyxps6f` (`finance-sandbox`), under `inputs/2026-10-27/`, with one Storage Blob Data Contributor role assignment for the owner's account — the container, the role assignment and the upload are Section 6 actions, presented as a Publish Request on 2026-10-27 and pending the owner's yes; until then the files are kept locally, unprinted. Two files stayed: the Stax endpoint notes (a test reads them) and the public Stax answers, which hold no business data.

**What remains in history.** Every moved or redacted file stays in every commit that held it, on
`main` and the merged branches, in any public clone taken while the repository is public (until
2026-10-31) and in GitHub's cache of the old blobs; only a history rewrite with a force-push to
`main` (Section 6.2: a human's action) and GitHub's cache purge would remove them.

**Gate.** ruff, `ruff format --check` (537 files), mypy strict (537 files), `uv lock --check`, `makemigrations --check` (no migration): clean. sqlite: the full suite's first run found the one test that reads the Stax endpoints note (8,167 passed, 1 failed; the note restored), then the adapter file 100 passed on aed51a7. PostgreSQL 16 (a throwaway container, the CI split): the migration selection 36 passed in 1,563 s; the unit selection 8,826 passed, 3 skipped, 125 deselected in 1,769 s (on the restored tree); the e2e suite 43 passed four times over (116, 109, 104 and 105 s). Visual: no baseline regenerated (no page changed); 66 passed on PostgreSQL and 66 on sqlite. Secret scans clean; the moved-value grep over the tree outside the QA records finds nothing.

**Verdict (B):** PASS for the repository side; the Azure side (container, role, upload) pending the owner's authorisation; residual: the public history keeps everything moved.
